PREREQUISITE P8

Reading the Course's TypeScript

The engine is written in a small, deliberate subset of TypeScript. This page covers every feature you'll see, and how to run it.

P8.1Why TypeScript?

One reason: the same file runs in two places. Node runs it from your terminal (tests, demos), and the webapp imports it into the browser (the Labs). There is no port and no copy, so the Lab you play with is the code you read. TypeScript's type checker also catches a large class of tree-handling mistakes before anything runs.

P8.2Tagged unions: "one of these shapes"

A value that can be one of several shapes is written as a union of object types, each carrying a kind field that says which shape it is. This is how the course writes the λ-term tree.

p8.ts

type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; side: number };

function area(s: Shape): number {
  switch (s.kind) {
    case "circle": return Math.PI * s.radius ** 2;
    case "square": return s.side * s.side;
  }
}

console.log(area({ kind: "square", side: 3 }));
console.log(area({ kind: "circle", radius: 1 }).toFixed(4));
const twice = (f: (x: number) => number) => (x: number) => f(f(x));
console.log(twice((x) => x + 1)(5));

Inside case "circle":, TypeScript knows s has a radius. This is called narrowing. If you forget a case, the checker complains that the function might not return a number. The engine's functions have exactly this shape, with one case per node kind (P3.3).

P8.3Running a .ts file

Node 22.6+ can run TypeScript directly by stripping the type annotations. It never type-checks. It just deletes them. This course was verified on Node v22.14.0:

Run it

node --experimental-strip-types --no-warnings p8.ts
Actual output:
9
3.1416
7
Getting an ExperimentalWarning?

Without --no-warnings, Node 22.14 prints ExperimentalWarning: Type Stripping is an experimental feature and might change at any time to stderr before the output. It's harmless. On Node 23.6+ the flag isn't needed at all. On Node older than 22.6 you'll get bad option: --experimental-strip-types, so upgrade Node.

Every module folder also has a package.json, so npm test and npm run demo run the same commands for you.

P8.4The rule the course follows: erasable syntax only

Because Node strips types instead of compiling them, TypeScript features that generate JavaScript code are not allowed: no enum, no namespace, no constructor parameter properties. Everything you see is plain JavaScript plus annotations that can be deleted. If you delete every : Type in the file, it's still a working JS program.

P8.5Imports use the .ts extension

import { Var, Lam, App } from "./term.ts";

Node requires the real file extension when stripping types. The webapp is configured (allowImportingTsExtensions) to accept the same import.

P8.6readonly and as const

Terms are never mutated (P3.4). The type definitions mark fields readonly, so any accidental t.body = … is a type error.

P8.7Tests: node:test

Each module's test.ts uses Node's built-in test runner: no libraries to install.

import { test } from "node:test";
import assert from "node:assert/strict";
test("identity prints as λx.x", () => { assert.equal(print(I), "λx.x"); });
