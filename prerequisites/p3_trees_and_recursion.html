PREREQUISITE P3

Trees & Recursion

A program is text on the outside and a tree on the inside. Every algorithm in this course walks that tree with a function that calls itself.

P3.1Text is flat, meaning is nested

The string 1 + 2 * 3 is a flat row of characters, but its meaning is nested: the multiplication happens inside the addition. A syntax tree makes that nesting explicit.

+ / \ 1 * / \ 2 3
The tree for 1 + 2 * 3. The parentheses and precedence rules are gone. Nesting says it all.

Programs are handled as trees, not strings, because trees are unambiguous. Once you have the tree, there's no question of what groups with what.

P3.2Abstract syntax trees (ASTs)

An abstract syntax tree drops the things that were only there to help humans read the text: parentheses, spaces, the dot in λx.. It keeps only the structure. Each node has a kind (what shape it is) and children (its sub-trees). A node with no children is a leaf.

The λ-calculus AST has exactly three node kinds:

KindWrittenChildren
Variablexnone (a leaf; stores a name)
Abstractionλx. Mone: the body M (also stores the name x)
ApplicationM Ntwo: the function M and the argument N

P3.3Recursion on trees: one case per node kind

To compute something about a whole tree, write a function with one case per node kind. Each case calls the function on its children and combines the results. The tree's shape is the shape of the code.

// Count the nodes in a λ-term (this exact function appears in Module 1)
function size(t) {
  switch (t.kind) {
    case "var": return 1;                              // leaf: just me
    case "lam": return 1 + size(t.body);               // me + my one child
    case "app": return 1 + size(t.fn) + size(t.arg);   // me + my two children
  }
}
Recursion on a tree is a manager delegating to their direct reports.

"How many people are in your department?" The manager asks each direct report the same question, adds up the answers, and adds one for themselves. Someone with no reports (a leaf) just answers "1." Nobody needs to see the whole company. Each person handles one level.

Why doesn't it loop forever? Every recursive call is on a strictly smaller tree, and trees are finite. Eventually every path hits a leaf. P5 turns this observation into a proof technique.

P3.4Transforming trees: build a new one, don't mutate

Many algorithms (renaming, substitution, reduction) produce a new tree from an old one. This course never mutates a tree in place. Each case returns a fresh node built from the transformed children. Unchanged sub-trees can be shared between the old and new trees safely, precisely because nothing mutates them.

P3.5A practical limit: stack depth

Each recursive call uses a slot on the host language's call stack. A tree 100,000 levels deep can overflow it. Most terms in this course are shallow, but some aren't. Module 20 (the Krivine machine) and Module 21 (CEK) exist partly to remove this dependence on the host stack.

P3.6Where this shows up

Everywhere. Module 1 defines the tree. Module 3 builds trees from text. Every later module is "one more recursive function over this tree."
