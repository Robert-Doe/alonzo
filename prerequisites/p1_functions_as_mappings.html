PREREQUISITE P1

Functions as Mappings

In the λ-calculus, functions are the only thing there is. Before building one, get clear on what a function is.

P1.1A function is a mapping, not a procedure

In school, f(x) = x + 1 looks like a recipe: "take x, add one." Mathematicians mean something more modest. A function is just a pairing of inputs with outputs, where every input gets exactly one output. f pairs 1 with 2, 2 with 3, 41 with 42, and so on.

A function is a vending machine with one slot and one tray.

Put a coin marked 3 in the slot, and the thing marked 4 drops into the tray. Every time. You don't need to know what gears are inside. Two machines that always drop the same thing for the same coin are, as mappings, the same function, even if their insides differ.

That last sentence has a name: extensionality. Two functions are extensionally equal if they agree on every input. It comes back in Module 11 as η-conversion.

P1.2Functions don't need names

f(x) = x + 1 does two things at once: it makes a function, and it names it f. The λ-calculus separates those. λx. x + 1 makes the function and names nothing. Read the λx. as "the function that takes x and returns…".

NotationSame idea in
λx. x + 1λ-calculus (Church, 1932)
x ↦ x + 1mathematics ("maps to")
x => x + 1JavaScript / TypeScript
lambda x: x + 1Python
fun x -> x + 1OCaml

Every one of those languages borrowed the idea, and Python and Lisp even borrowed the word, from Church.

P1.3Functions are values

If a function is just a thing, you can hand it to another function, or get one back as a result. A function that takes or returns functions is called higher-order.

// twice takes a function f and returns a NEW function
const twice = (f) => (x) => f(f(x));
const addOne = (x) => x + 1;
twice(addOne)(5)   // → 7

In the pure λ-calculus there are no numbers, no strings, no booleans. There are only functions. Everything else (numbers in Module 14, booleans in Module 13) is built out of functions that take and return functions.

P1.4Currying: every function takes exactly one argument

λ-calculus functions take one argument. So how do you write addition, which needs two? You write a function that takes the first number and returns a function waiting for the second:

add      = λx. λy. x + y
add 3    = λy. 3 + y          ← a function, waiting
add 3 4  = 7

This trick is called currying, after Haskell Curry. It was actually published first by Moses Schönfinkel in 1924, and you'll rebuild his paper in Track H1. It explains two notation rules you'll meet constantly:

  • f a b means (f a) b: apply f to a, then apply the result to b. Application is left-associative.
  • λx. λy. body is often abbreviated λx y. body.
Sharpen your pencil

With add = λx. λy. x + y, what is add 10? Is it a number?

Answer: no. It is the function λy. 10 + y. Currying means partial application is free.

P1.5Application is juxtaposition

In most languages you call a function with parentheses: f(x). In the λ-calculus you just put the function next to its argument: f x. Parentheses are only for grouping, never for calling. (f x) and f x are the same term. f (g x) means "apply g to x, then feed that to f."

P1.6Where this shows up

  • Module 1 builds a data type with exactly three shapes: variable, function (λ), application.
  • Module 3 implements the left-associativity rule from P1.4 in the parser.
  • Modules 13–16 build booleans, numbers and lists out of nothing but functions.
  • Module 11 turns extensionality (P1.1) into a reduction rule.
