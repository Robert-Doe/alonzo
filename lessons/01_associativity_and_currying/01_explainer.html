Associativity & Currying

01The Big Analogy

Associativity is the rule for who holds hands first in a line of people.

Line up a − b − c. If everyone links arms from the left, a and b pair up first and then the pair grabs c: (a − b) − c. Linking from the right pairs b and c first: a − (b − c). Same people, different groups, different answers (10−4−3 is 3 one way and 9 the other).

For addition, it doesn't matter who links first: (a+b)+c = a+(b+c). That property is associativity in the algebraic sense. For operators where it does matter, a language must pick a side, and the choice is called the operator's associativity in the parsing sense: left-associative or right-associative.

Two meanings of one word

Algebraic: an operation is associative if grouping never changes the result (+, ×, function composition). Parsing: an operator is left- or right-associative if, by convention, an ungrouped chain groups from that side. The second is needed exactly when the first fails.

02The Three Conventions of the λ-Calculus

  1. Application is left-associative. f a b c = ((f a) b) c. Every function takes one argument and may return a function, so the leftmost application happens first. That's currying.
  2. A λ-body extends as far right as possible. λx. x y = λx. (x y), and λx. λy. M = λx. (λy. M). Binders nest to the right.
  3. Function types are right-associative (from Module 24). A → B → C = A → (B → C): "takes an A, returns a function from B to C". It's the mirror of rule 1.

Rules 1 and 3 must point in opposite directions, or currying stops lining up. Deep dive 2 shows why.

03The Map: What the Engine Actually Does

Real output from the Module 13 engine: parse, then print fully parenthesized (printFull) and minimally (print):

f a b c            → (((f a) b) c)                 print: f a b c
f (a b) c          → ((f (a b)) c)                 print: f (a b) c
λx. λy. x y        → (λx. (λy. (x y)))             print: λx. λy. x y
λx y. x y z        → (λx. (λy. ((x y) z)))         print: λx. λy. x y z
(f a) b            → ((f a) b)                     print: f a b
f a (b c)          → ((f a) (b c))                 print: f a (b c)
Left-associative application makes left-leaning trees. Right-extending λs make right-leaning chains.

04The Code, Explained

Left-associativity in the parser: a loop, not left recursion

track1-engine/03_parser/src/parser.ts

let acc = parseItem();
while (startsItem(peek().kind)) acc = App(acc, parseItem());   // ((f a) b) c

Right-extension in the parser: the body is a whole term

const body = parseTerm();                                   // eats everything to the right
return params.reduceRight((b, p) => Lam(p, b), body);       // λx y. M → λx. (λy. M)

And in the printer: parentheses exactly where a convention would regroup

const arg = t.arg.kind === "app" ? `(${go(t.arg, true)})` : go(t.arg, trailing);   // f (a b), not f a b

reduceLeft builds left-leaning trees and reduceRight builds right-leaning ones. Look for which fold a parser uses, and you've found the associativity.

07Brain Exercise

Think before you reveal

Suppose a λ-calculus dialect made application right-associative, so f a b meant f (a b). How would you then write "apply the curried two-argument function f to a and b"? And what would happen to the readability of S = λx y z. x z (y z)?

Reveal the answer

You'd have to write (f a) b every single time, which is the most common thing curried code does. Meanwhile the rare "apply to the result of an application" would get the short form. S's body x z (y z) would need to become ((x z) (y z)). Left-associativity isn't arbitrary. It makes the common case, multi-argument calls, need no parentheses. That same reasoning makes → right-associative: the common type "curried function of two arguments" is A → B → C with no parentheses.

08There Are No Dumb Questions

Is function composition left- or right-associative?

Algebraically it's associative: (f∘g)∘h = f∘(g∘h), so grouping never changes the meaning. Languages still pick a parsing convention for chains. Haskell's . is declared right-associative.

Is associativity the same as precedence?

No. Precedence decides between different operators (a + b * c). Associativity decides within a chain of the same operator (a - b - c). In the λ-calculus, "application binds tighter than λ" is the precedence rule, and "application is left-assoc" is the associativity rule.

Why does the tree for f a b c lean left?

Because the first thing to happen is f a, which becomes the function part of the next application. The deepest node is the first computation.
