Left vs Right in Parsers

Right-associativity falls out of recursion for free. Left-associativity fights recursive descent, and the fix is the same loop Module 3 uses.

The grammar that says it directly

left:   E ::= E "-" T | T        (a - b - c = (a - b) - c)
right:  E ::= T "^" E | T        (a ^ b ^ c = a ^ (b ^ c))

Each rule puts the recursion on the side the operator groups toward. That's the textbook way to describe associativity with a grammar (P4.3).

Right: recursion does it for you

function parsePow() {
  const left = parseAtom();
  if (peek() === "^") { next(); return Pow(left, parsePow()); }   // recurse on the RIGHT
  return left;
}

The recursive call handles "everything to the right", so a ^ b ^ c becomes Pow(a, Pow(b, c)). The λ-body rule works exactly like this: parseLambda calls parseTerm for the whole body, so bodies extend right.

Left: recursion would loop forever

Transcribe E ::= E "-" T literally and parseE's first action is to call parseE, before consuming any token. That's infinite recursion. It's the left-recursion problem from Module 3. The standard fix is to rewrite the rule as repetition and fold to the left:

let acc = parseT();
while (peek() === "-") { next(); acc = Sub(acc, parseT()); }    // ((a - b) - c)

Module 3's application loop is the same shape with no operator token: two items next to each other are the operator.

Other parser families

LR parsers (yacc/Bison) handle left recursion natively and take associativity declarations like %left '-' and %right '^' to resolve shift/reduce conflicts. Pratt parsers give each operator a binding power, and right-associativity is "recurse with one less". Both are covered in the sibling course bob_compiler/a-finity/everything_parsing.

How this connects

The λ-calculus needs just the two shapes above: a loop for application and a recursive call for bodies. Track 2's Alonzo-ML parser (C1) will need both, for real infix operators.
