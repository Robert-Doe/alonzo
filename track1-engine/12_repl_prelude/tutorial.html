00Prerequisites

From the course: capture-avoiding substitution (generalized here to many names at once), and strategies and normal forms, which the REPL's commands expose.

01The Big Analogy

A definition is a text-expander shortcut, not a new word in the language.

Type ;addr and your laptop replaces it with your full address before the email is sent. The recipient never sees ;addr, and the mail system never needs to know shortcuts exist. Delete every shortcut and you can still send the exact same email, just with more typing.

That's a λ-calculus definition. S K K a is expanded to (λx y z. x z (y z)) (λx y. x) (λx y. x) a before reduction starts, so the reducer never sees a name. It also explains the one thing shortcuts can't do: a shortcut that expands to itself would never finish expanding. So fact = … fact … is refused. Recursion has to come from inside the calculus (Module 15).

02What Happens, Step by Step

  1. The lexer now recognizes =. A line name = term is a definition, :word … is a command, and anything else is an expression.
  2. define refuses a body that mentions its own name, expands all earlier names inside the body, and stores both versions.
  3. For an expression, expand replaces every defined name at once, with substMany (simultaneous, capture-avoiding).
  4. The raw term is reduced with the session's strategy (normal order by default) and fuel.
  5. The result is printed, plus = NAME if it matches some definition's normal form.
  6. execLine is pure, so the terminal CLI and the browser Lab are just loops around it.

04The Code, Explained

A definition is expanded when it's made

src/defs.ts

export function define(defs: Defs, name: string, source: Term): DefineResult {
  if (freeVars(source).has(name))
    return { ok: false, error: `'${name}' mentions itself. …` };
  const body = expand(source, defs);          // earlier names are baked in now
  // … store { name, source, body } …
}

Simultaneous substitution

export function substMany(t: Term, map: ReadonlyMap<string, Term>): Term {
  switch (t.kind) {
    case "var": return map.get(t.name) ?? t;             // replacements are NOT re-scanned
    case "app": return App(substMany(t.fn, map), substMany(t.arg, map));
    case "lam": /* drop the shadowed name; rename the binder if a replacement would be captured */
  }
}

Why not substitute names one at a time? Try swapping: {x ↦ y, y ↦ x} on x y. Sequentially you get x x or y y. Simultaneously you get y x, and the demo prints exactly that.

A REPL with no I/O

export function execLine(s: Session, line: string): { session: Session; output: string[] } { /* … */ }

The terminal (repl-cli.ts) and the browser (Lab 12) both call this and print the lines it returns. Same code, same answers.

BULLET POINTS
  • Definitions are macros, expanded before reduction. They add no power (500/500 random programs agree).
  • A definition can't mention itself. Recursion needs a fixed-point combinator (Module 15).
  • Expansion substitutes all names at once, and still avoids capture.
  • The REPL is a pure function from (session, line) to (session, output).

05Limits: What You Cannot Do Yet

Can't do yet

  • Define recursive functions by name (Module 15).
  • Write numbers or booleans. Those are the next two modules, built from λ.
  • Give definitions types (Module 24 onward).
  • Use Unicode names like Ω. Identifiers are ASCII (Module 2), hence Omega.

Can do now

  • Name terms and reuse them, from a prelude file or interactively.
  • Evaluate with any strategy, fuel, and optional traces.
  • Inspect expansions, de Bruijn forms and normal-form classes from the prompt.
  • Run scripts: npm run repl -- file.lam.

Getting a blank or broken result?
  • A name isn't expanded: names are case-sensitive, and the definition must come before its use. :defs lists what's in scope.
  • "mentions itself": that's a recursive definition, which macros can't express. Wait for Module 15.
  • You redefined K and S still behaves the old way: expansion is static. S was expanded when it was defined. The REPL warns you.

07Brain Exercise

Think before you reveal

twice twice f x gives f (f (f (f x))): four applications. Now define thrice = λf x. f (f (f x)).

Before evaluating, predict how many times f is applied in (a) thrice twice f x and (b) twice thrice f x. Are they the same? What arithmetic operation is "putting one of these in front of another"? The Lab's checker takes your two numbers.

Check your predictions in the Lab
Reveal the answer

(a) 8, and (b) 9. Not the same! (Verified: the REPL prints eight and nine fs.)

thrice twice means "apply twice, three times": doubling three times gives 2 × 2 × 2 = 2³ = 8. twice thrice means "apply thrice, twice": 3 × 3 = 3² = 9. So putting n in front of m computes mⁿ, exponentiation by pure function application. (And thrice thrice f x gives 27 = 3³.)

That's no accident. twice and thrice are the numbers 2 and 3, written as "apply f this many times." They're called Church numerals, and Module 14 builds all of arithmetic on them. Exponentiation turns out to be the easiest operation.

08There Are No Dumb Questions

If definitions add no power, why bother?

For humans. S K K is readable, and its expansion is not. The theorem "no power added" is what lets us use them without worrying: anything proved about raw terms still holds.

How do real languages allow recursive definitions then?

They add something the pure calculus doesn't have: a let rec construct, or a built-in fixed-point operator. Under the hood, let rec f = … f … becomes Y (λf. …) (Module 15) or a special runtime mechanism (Track 2).

Why static expansion instead of looking names up at evaluation time?

Because looking names up late is dynamic scope: redefining a helper would silently change every function that used it. Early LISP worked that way and it caused bugs (Track H5).

Why ASCII names only?

The lexer's identifier rule (Module 2) is ASCII letters, digits, _ and ', the same rule the printer relies on. Allowing Ω would mean widening both, and λ itself would have to stay reserved.

09What's Next

The REPL can name things, but it still has nothing to compute with: no true/false, no numbers, no pairs. Module 13 builds the first data out of pure functions: Church booleans (a boolean is a choice between two things) and pairs (a pair is a function waiting for a selector). It adds them to the prelude, verifies every truth table by reduction, and shows why if must be lazy, reusing Module 9's strategies.
