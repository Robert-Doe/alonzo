Free Variables & α-Equivalence

01The Big Analogy

Every λ is a household that coins its own nickname.

Picture houses nested inside each other, like rooms within rooms. The header λx. means "in this house, 'x' is what we call the guest who arrives at the door." Everyone inside uses the nickname.

  • Bound use. Someone inside says "x" and means their house's guest. If they're inside two houses that both coined "x", they mean the nearest one, the house they're standing in. That's shadowing.
  • Free use. Someone says "y", but no house around them ever coined "y". They must mean someone from outside all the houses, like a neighbor down the street.
  • α-conversion. A family can change its nickname from "x" to "Kiddo" throughout the house and nothing changes. Everyone still means the same guest. That's why λx. x and λy. y are the same function.
  • Capture (the danger). If the family picks a new nickname that someone in the house already uses for the neighbor ("y"), then "y" now means two people, and the neighbor gets confused with the guest. A careful family checks before renaming.

This module teaches the engine to answer "who is 'x' here?" for every name. That is binding, and it's the first thing in the course about meaning rather than spelling.

02What Happens, Step by Step

  1. freeVars(t) applies three equations recursively. A variable is free in itself. A λ removes its own name from its body's free set. An application unions both sides.
  2. occurrences(t) walks the tree carrying a scope, a stack of the binders passed so far. At each variable, it searches the scope from the innermost outward for a matching name.
  3. alphaEquivalent(a, b) walks both trees together with two scopes. A bound variable is compared by how many binders out its λ is. A free variable is compared by name.
  4. renameBinder(λx. M, y) checks two capture conditions before renaming. If either fails, it refuses and explains why.
  5. canonicalize(t) renames every binder to v0, v1, … in order, giving a second, independent α-test: equal canonical forms ⇔ α-equivalent.

03The Map: Who Binds Whom

The term (λx. λx. x y) x has three variable uses. Here's what occurrences reports (real demo output):

  y at fn.body.body.arg   FREE

Three x's, three different fates. The outer λx binds nothing: the inner one shadows it, and the final x is outside both.

04The Code, Explained

Free variables: three equations, three cases

src/alpha.ts

//   FV(x)     = { x }
//   FV(λx. M) = FV(M) − { x }
//   FV(M N)   = FV(M) ∪ FV(N)
export function freeVars(t: Term): Set<string> {
  switch (t.kind) {
    case "var": return new Set([t.name]);
    case "lam": { const s = freeVars(t.body); s.delete(t.param); return s; }
    case "app": { const s = freeVars(t.fn); for (const v of freeVars(t.arg)) s.add(v); return s; }
  }
}

Same skeleton as size in Module 1. The only new idea is in the λ case: a binder removes its name from what it sees below.

α-equivalence: compare distances, not names

function distance(name: string, scope: string[]): number {
  for (let i = scope.length - 1; i >= 0; i--) if (scope[i] === name) return scope.length - 1 - i;
  return -1; // free
}
// … in the var case:
const da = distance(a.name, sa), db = distance(b.name, sb);
return da === db && (da !== -1 || a.name === b.name);

In λx. λy. x, the body's x is at distance 1 (skip one binder, λy, to reach it). In λa. λb. a, the body's a is also at distance 1. Same distance, so the same variable, whatever it's called. Free variables have no distance, so they must match by name. That distance is the de Bruijn index you'll build in Module 6.

Renaming a binder: the two capture checks

if (freeVars(t.body).has(y))                                  // (1) an outside y would be captured
  return { ok: false, reason: `'${y}' is free in the body, so the new λ${y} would capture it` };
// (2) while renaming x→y in the body, note if we're under an inner λy:
case "lam":
  if (u.param === x) return u;                               // shadowed: these x's aren't ours
  return Lam(u.param, go(u.body, underY || u.param === y));
BULLET POINTS
  • "Free" is always relative to a term: the same occurrence is free in x y and bound in λx. x y.
  • A variable use belongs to its nearest enclosing binder with the same name.
  • α-equivalence ignores bound names, but never free ones.
  • Renaming is safe only if it can't change any use's binder. Otherwise it's capture.

05Limits: What You Cannot Do Yet

Can't do yet

  • Substitute a term for a variable (Module 5). Renaming is only the special case "substitute a variable."
  • Fix a capturing rename automatically. Here it's refused. Module 5 renames the obstructing inner binder instead.
  • Rename a binder that isn't the outermost λ.
  • Store terms "up to α" so equality is instant (Module 6's de Bruijn indices).

Can do now

  • Compute free variables, and tell closed terms (combinators) from open ones.
  • Point every variable use at its binder, shadowing included.
  • Decide α-equivalence in two independent ways.
  • Detect both kinds of variable capture.

Getting a blank or broken result?
  • "(λx. x) x has FV {x}? But x is bound!" Only the first x is. The last one is outside the λ's parentheses, so it's free. FV is about occurrences, not spellings.
  • A rename you expected to work is refused: read the reason. It names which of the two capture conditions failed. Pick a name that's neither free in the body nor bound by an inner λ over an x.

07Brain Exercise

Think before you reveal

K = λx. λy. x takes two arguments and returns the first. Suppose someone "tidies it up" by renaming the outer binder to y, mechanically replacing x with y everywhere.

(1) What term do they get, and what does it do with two arguments? (2) Which of the two capture conditions does the engine cite? (3) Of all possible single-letter names, which ones can the outer binder of K safely be renamed to?

Try renames in the Lab
Reveal the answer

(1) The mechanical rename gives λy. λy. y. By shadowing, that final y now refers to the inner λ, so the function returns its second argument. K has silently become a different function (sometimes called K*). The demo shows the engine refusing: REFUSED: an occurrence of x inside an inner λy would become 'y' and be captured by that inner λy.

(2) Condition (2): a free x of the body sits under an inner λy. Condition (1) is fine, since K's body has no free y. K is closed.

(3) Every name except y. K has no free variables, so condition (1) can never fail, and the only inner binder is λy. So a, z, q, even x (a no-op) are all fine. Try z in the Lab: λz. λy. z. This is the whole story of capture in miniature, and Module 5 turns "refuse" into "rename the inner binder out of the way."

08There Are No Dumb Questions

Why build two α-equivalence algorithms? Isn't one enough?

One is enough if it's right. Two that share no code, checked against each other on 3000 random pairs, is how you gain confidence it is right. If they ever disagreed, one of them would have a bug, and the failing pair would be printed.

If λx. x and λy. y are "the same," why does the engine store them differently?

Because a tree with names has to store some name. Textbooks quietly say "we identify α-equivalent terms." Implementations must choose: keep names and compare with alphaEquivalent (this module), or drop names entirely (Module 6).

What does ε mean in a path?

The empty path: the root of the tree itself. A path like fn.body means "go into the function part, then into the λ's body." Module 7 names redexes by their paths.

When would anyone care about free variables? Real programs are closed.

Whole programs are, but their pieces aren't. The body of λx. x y, taken on its own, has y free. Every reduction step (Module 8) works on pieces, and compilers (Track 2 C7) must compute exactly which free variables each function captures in its closure.

Can the canonical names v0, v1 clash with names the user wrote?

With free names, no: canonicalize skips them (λx. v0 becomes λv1. v0). With bound names, it doesn't matter, because every binder is renamed.

09What's Next

Renaming is the gentlest special case of substitution: replacing a variable with another variable. Module 5 replaces a variable with an arbitrary term, M[x := N]. That operation is at the heart of computation (β-reduction, Module 8). It hits the same capture danger at full strength: substituting y into λy. x naively gives λy. y. We'll watch naive substitution fail on real examples, then fix it by renaming binders to fresh names, the step this module only refused.
