01The Big Analogy

A de Bruijn index is "my grandparent" instead of "Alice."

Picture a family tree where every λ is a generation. A named variable says "give this to Alice." But many families have an Alice, and renaming one breaks every note that mentions her. A de Bruijn index says "give this to my ancestor 2 generations up." That's a relation, not a name.

  • Names stop mattering. Two families with differently named people but the same shape give the same "2 generations up" notes. That's α-equivalence as equality.
  • The same person gets different numbers. To you, Alice is "1 up." To your child, the same Alice is "2 up." One variable, different indices at different depths.
  • Shifting. If you slip a note saying "1 up" into your child's pocket, it must be rewritten as "2 up" for the child. Otherwise it reaches the wrong person.
  • Capture, renamed. Forgetting to rewrite the note is exactly capture. The note meant your parent, but now it names the child's parent: you.

So names don't disappear for free. The capture problem turns into an arithmetic problem, which computers are much better at than inventing fresh names.

02What Happens, Step by Step

  1. toDeBruijn(t, Γ) walks down, keeping the enclosing binder names innermost-first. A bound variable becomes its position in that list.
  2. A free variable becomes (number of enclosing binders) + (its position in Γ). Γ defaults to the free variables, sorted.
  3. λ nodes lose their names. The old name is kept only as a display hint.
  4. fromDeBruijn(d, Γ) goes back, choosing binder names from hints and freshening them so nothing is captured.
  5. shift(d, c, t) adds d to every index ≥ c. The cutoff grows by one under each λ, protecting indices bound inside.
  6. substTop(body, s) shifts s up, replaces index 0 in the body (shifting s once more under each λ), then shifts everything down because the binder is gone.

04The Code, Explained

Converting: the index is a position in the scope list

src/debruijn.ts

// scope[0] is the INNERMOST binder, so a bound variable's index is just its position.
case "var": {
  const i = scope.indexOf(u.name);
  if (i >= 0) return DVar(i);
  const j = ctx.indexOf(u.name);
  if (j < 0) throw new Error(`free variable '${u.name}' is not in the naming context [${ctx.join(", ")}]`);
  return DVar(scope.length + j);
}
case "lam": return DLam(go(u.body, [u.param, ...scope]), u.param);

Pushing the new binder at the front makes indexOf find the innermost match first. That's shadowing, for free.

Shifting: move only what points outside

export function shift(d: number, c: number, t: DTerm): DTerm {
  switch (t.kind) {
    case "var": return t.index >= c ? DVar(t.index + d) : t;
    case "lam": return DLam(shift(d, c + 1, t.body), t.hint);
    case "app": return DApp(shift(d, c, t.fn), shift(d, c, t.arg));
  }
}

The cutoff c counts λs passed inside the term. An index below c points at one of those, so it travels with the term and must not change. Demo: shift(+2, 0, λ. 0 1) = λ. 0 3. The bound 0 stays, and the free 1 moves.

Substitution: shift the replacement under every λ

export function substDB(j: number, s: DTerm, t: DTerm): DTerm {
  switch (t.kind) {
    case "var": return t.index === j ? s : t;
    case "lam": return DLam(substDB(j + 1, shift(1, 0, s), t.body), t.hint);
    case "app": return DApp(substDB(j, s, t.fn), substDB(j, s, t.arg));
  }
}
export function substTop(body: DTerm, s: DTerm): DTerm {
  return shift(-1, 0, substDB(0, shift(1, 0, s), body));
}
BULLET POINTS
  • A de Bruijn index is the number of λs between a variable and its binder.
  • α-equivalent terms become identical nameless trees, so equality is structural.
  • Moving a term under a λ requires shifting its free indices up by one.
  • Forgetting that shift is capture, in numeric form.

05Limits: What You Cannot Do Yet

Can't do yet

  • Read nameless terms comfortably. Humans are bad at "2 λs out," which is why named terms stay primary.
  • Compare terms that were converted with different contexts. Γ must be shared.
  • Reduce anything. substTop is the β-step's substitution, but choosing redexes starts in Module 7.
  • Avoid shifting cost: every substitution walks and rebuilds the argument. Environments (Module 19) and levels (Module 23) avoid it.

Can do now

  • Convert named ↔ nameless without losing anything (3000/3000 round trips).
  • Decide α-equivalence by plain structural equality.
  • Substitute with no fresh names, matching Module 5's results exactly.
  • Explain capture as a missed shift.

Getting a blank or broken result?
  • free variable 'y' is not in the naming context: you passed a Γ that doesn't list every free variable. Omit it to use the default, or add the name.
  • Two α-equivalent open terms compare unequal: each was converted with its own default Γ. Pass one shared context to both.
  • "(λ. 0) 0: why is y zero?" At the top level there are no binders, so the first free variable in Γ is index 0 + 0. Under the λ, the same 0 means the bound variable.

Reveal the answer

λ. λ. 1 (λ. 0 2), which the engine prints as λ. λ. 1 λ. 0 2 (the trailing λ needs no parentheses, same rule as Module 1).

  • First x: under λy only, so it crosses 1 binder → 1.
  • z: its own binder is the nearest → 0.
  • Second x: under λz and λy, so it crosses 2 → 2.

Same variable, different depths, different numbers. An index is a relative address. That's also why moving a term one λ deeper requires adding 1 to its free indices. The "2 generations up" note must become "3 up" in the child's pocket. Skip it and the index points at a closer λ: the demo shows (λy. x)[x := y] becoming λ. 0, the identity, instead of λ. 1. It's Module 5's capture, reproduced with arithmetic.

08There Are No Dumb Questions

Who was de Bruijn, and why did he want this?

Nicolaas Govert de Bruijn, a Dutch mathematician, introduced the notation in 1972 while building Automath, one of the first computer systems for checking mathematical proofs. A machine checking proofs needs α-equivalence to be trivial, and this makes it so. Track H8 rebuilds an Automath-style checker.

Do real systems actually use this?

Yes. Proof-assistant kernels (Coq/Rocq, Lean) represent bound variables with de Bruijn indices, and many compilers use them internally. Lean and many others use the locally nameless variant: indices for bound variables, names for free ones. DECISIONS.md explains why we chose pure indices here.

Isn't shifting just as error-prone as fresh names?

It's error-prone in a different, more testable way. A missed shift is an off-by-one that fails deterministically on small examples. Name capture can hide for a long time (Module 5's "stealth capture"). Many implementers still prefer one over the other, which is why both exist.

What are de Bruijn levels?

The mirror image: count binders from the root down instead of from the variable up. With levels, a variable's number doesn't change when you go deeper, but it does when you move a term to a different root. Module 23 (normalization by evaluation) uses both: indices for terms, levels for values.

Why keep named terms at all, if nameless ones are so much cleaner?

Because people read and write names. The usual architecture, which this course follows from here on, is: humans type named terms, the engine converts to nameless for comparisons and heavy lifting, and converts back to show results.

09What's Next
