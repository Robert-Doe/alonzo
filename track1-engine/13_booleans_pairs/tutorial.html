MODULE 13

Church Booleans & Pairs

The calculus has no true, no false, no data at all, only functions. So we make data out of behaviour: a boolean is a choice, and a pair is a function waiting to be asked a question.

01The Big Analogy

A Church boolean is a railway switch, and a pair is a locker with two compartments.

true is a switch set to the left track, false to the right. It has no "value" to inspect. You send it two trains, t and f, and it lets exactly one through: true t f = t. That's all a boolean ever does. So if b then x else y is just b x y: the switch is the if.

A pair pair a b is a locker holding a and b. It won't show you its contents. It waits for you to hand it a switch and gives you whichever compartment the switch points at: fst p = p true, snd p = p false.

02What Happens, Step by Step

  1. prelude.lam gains true, false, if, not, and, or, xor, pair, fst, snd and swap, all plain definitions (Module 12).
  2. Evaluating and true false expands every name, then reduces with normal order.
  3. The REPL names the result: λt. λf. f = false.
  4. From TypeScript, decodeBool normalizes a term and checks whether it's α-equal to true or false. null means "not a boolean".
  5. truthTable encodes every input combination, applies the operator, reduces and decodes. Every table row is a real computation.

04The Code, Explained

The prelude additions

prelude.lam

true  = λt f. t              -- choose the first  (the same term as K)
false = λt f. f              -- choose the second (the same term as KI)
if    = λb t e. b t e        -- "if" does nothing: the boolean does the choosing
not   = λb. b false true
and   = λp q. p q false
or    = λp q. p true q
pair  = λa b s. s a b
fst   = λp. p true
snd   = λp. p false

Decoding: the only way to ask "is this true?"

src/church.ts

export function decodeBool(t: Term, opts?: RunOptions): boolean | null {
  const r = normalize(t, opts);
  if (r.status !== "done") return null;
  if (alphaEquivalent(r.result, TRUE)) return true;
  if (alphaEquivalent(r.result, FALSE)) return false;
  return null;
}

No tag says "I'm a boolean". A term is true exactly when its normal form is λt f. t. Here, normalization and α-equivalence (Modules 4 and 9) are the type system.

BULLET POINTS
  • A boolean is a choice between two arguments. if is redundant.
  • A pair is a function waiting for a selector, and the selectors are booleans.
  • true is literally K. Data and code are the same stuff.
  • if must not evaluate both branches, so strict strategies need thunks.

Getting a blank or broken result?
  • The result prints as λt. λf. t instead of true: it is true. The REPL adds = true when naming is on. In TypeScript, use decodeBool.
  • if hangs under :strategy cbv: expected. Both branches are arguments, so they're evaluated first. Wrap them in λd. and apply the result to I.
  • decodeBool returns null: the term's normal form isn't exactly true or false (or it ran out of fuel).

07Brain Exercise

Think before you reveal

Implication p → q is false only when p is true and q is false.

Define implies using nothing but the booleans p and q themselves, plus true/false: no if, not, and or or. Hint: read your definition out loud as "if p then … else …". Then: why does the same trick make if itself unnecessary?

Check your definition in the Lab
Reveal the answer

implies = λp q. p q true, read as "if p then q, else true". If p is false, the implication holds. If p is true, it holds exactly when q does. The Lab's checker confirms the table F F → T, F T → T, T F → F, T T → T by reduction.

The trick is that a boolean is an if: p x y already means "if p then x else y". Every two-way decision can be written by applying the boolean. That's why if = λb t e. b t e is just η-expanded identity on booleans. We keep it only because it reads well.

08There Are No Dumb Questions

If true and K are the same term, how does the REPL know which name to print?

It doesn't know: the term is the same. It prints the most recently defined matching name, which is true because booleans come later in the prelude. In the untyped calculus, meaning comes from how a term is used.

What happens if I pass a non-boolean to not?

It computes something. not (λx. x) reduces happily, and the result just isn't a boolean (it decodes to null). No error, because nothing in the calculus can raise one. Types (Module 24) exist precisely to reject such programs before they run.

Is this how real computers do booleans?

No, hardware uses bits. But the idea survives everywhere: pattern matching, visitor objects, and Optional.map(ifPresent, ifAbsent)-style APIs are all "the data picks which branch runs". Track 2's compiler turns Church-style choices into real branches.

Can I build triples and records?

Yes, by nesting pairs: pair a (pair b c) is a triple, with fst (snd t) getting b (in the demo). Module 16 compares this with other encodings where records and lists are cheaper.

09What's Next

Module 12's Brain Exercise already met twice and thrice, which act like the numbers 2 and 3. Module 14 makes that official: Church numerals, where n is "apply f n times". Addition, multiplication and exponentiation fall out of iteration. Predecessor is famously hard, and the story goes that Kleene discovered the pair trick for it at the dentist.
