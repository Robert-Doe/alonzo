CONCEPT

Binder

The λx. part of an abstraction: the place where a name is introduced.

In one sentence

A binder is the declaration λx. that creates the name x for its body. It's where a variable is born, not where it's used.

A binder is the name tag printed at the door of a room.

The tag says "inside, we'll call the guest x." The tag itself isn't a person talking about x. It's the announcement that makes talking about x possible.

See it

λx. x y
^^
binder: introduces x

In the engine, a binder is the param field of a { kind: "lam" } node. It is not a { kind: "var" } node. That's why counts(λx. x) reports vars: 1: only the body's x is a variable occurrence (Module 1).

Shorthand λx y. M contains two binders: it's λx. λy. M.

Common mix-up

Wrong

"In λx. x, both x's are bound variables."

Right

The first x is the binder. The second is a bound occurrence, a use that refers back to the binder.

How this connects to the other terms

A binder defines a scope: its body. Every use of its name inside that scope is a bound variable. Uses with no matching binder around them are free variables. When a careless rename or substitution puts a free name under a binder with the same name, that binder grabs it: that's capture.
