CONCEPT

Variable Capture

The bug where a free name gets moved under a binder of the same name, and silently changes which variable it refers to.

In one sentence

Capture happens when an operation (renaming, substitution) turns a free occurrence into a bound one, or re-binds an occurrence to a different λ. The text looks plausible, but the meaning has changed.

Capture is a letter for the neighbor delivered into a house where a resident has the same nickname.

The envelope says "for y." Outside, y was the neighbor. But you carried it through a door whose tag says "here, y means our guest," and now the guest opens it.

See it (real output of npm run demo)

(λy. x)[x := y]
  naive   : λy. y                  FV = {}
  correct : λy1. y                 FV = {y}   renamed y→y1
  same meaning? false

λy. x is a constant function: it ignores its argument and returns whatever x is. Substituting the outside y for x should give "ignore the argument, return the outside y." Naive substitution gives λy. y, the identity. The fix, from Curry: rename the binder to a fresh name first (y1), then substitute.

Common mix-up

Wrong

"λx. λx. x is an example of capture."

Right

That's shadowing, a legal and intended nesting that you wrote on purpose. Capture is a change in binding caused by an operation on the term. Shadowing is a fact about the source. Capture is a bug in a transformation.

Subtle

Checking free variables before and after does not catch every capture. If a captured name also appears free elsewhere, FV is unchanged. Module 5's demo found 414 captures in 3000 random substitutions, and only 192 of them changed FV. See the tutorial's Brain Exercise.

How this connects to the other terms

Capture needs all four other ideas at once: a free variable in the incoming term, moved into the scope of a binder with the same name, where it wrongly becomes a bound variable. Avoiding it (fresh renaming) is what makes substitution, and therefore β-reduction, correct.
