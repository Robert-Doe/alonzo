00Prerequisites

P1.1 extensionality P6.2 normal forms

From the course: head and weak-head redexes (Module 7), the strategies that stop at each form (Module 9), and uniqueness via Church–Rosser (Module 10). The five forms are easy to mix up, so there's a vocabulary web for them.

01The Big Analogy

Five levels of "done" for a parcel.
  • Value / weak head normal form: it's a sealed box, and you can see that it's a box. You haven't opened it. It might even be full of an endless supply of packing peanuts (λx. Ω).
  • Head normal form: you've opened the box far enough to read the name on the top item, a variable. Whatever else is inside, that label can't change.
  • β-normal form: everything is unpacked, down to the last sub-package. No envelope anywhere is left unopened.
  • βη-normal form: unpacked and every pointless re-wrapping removed. A box whose only content is "forward this to f" is replaced by f itself.

A lazy language hands over the sealed box (WHNF). A theorem about "meaningful" terms needs the label (HNF). Comparing two programs for equality wants everything unpacked (β-NF or βη-NF).

02What Happens, Step by Step

  1. classifyForms(t) asks five questions, each answered by an earlier module: any β-redex? any η-redex? a head redex? a weak-head redex? is it a λ or a variable?
  2. η-reduction λx. M x → M (x ∉ FV(M)) was already a legal step. Now a strategy can choose it: normalOrderBetaEta.
  3. Module 9's run now honours the redex kind a strategy returns, a one-line change.
  4. Four normalizers each run the strategy that stops exactly at their form: call-by-name → WHNF, head reduction → HNF, normal order → β-NF, βη normal order → βη-NF.
  5. etaExpand(M) goes the other way, M ↦ λx. M x, with x fresh.

04The Code, Explained

Four predicates, all borrowed

src/normal.ts

export const isBetaEtaNormal = (t: Term) => findRedexes(t, ["beta", "eta"]).length === 0;
export const isHNF  = (t: Term) => headRedex(t) === null;
export const isWHNF = (t: Term) => weakHeadRedex(t) === null;
// isBetaNormal: Module 7.  isValue: Module 9.

Module 7 defined where the head redex is. "No head redex" is head normal form. Reusing the definitions means the two can never drift apart.

Normalizers are just strategies with a destination

export const normalOrderBetaEta: Strategy = { name: "normal order (βη)", pick: t => leftmostOutermost(t, ["beta", "eta"]) };

export const toWHNF     = (t, o?) => run(t, callByName, o);
export const toHNF      = (t, o?) => run(t, headReduction, o);
export const toBetaNF   = (t, o?) => run(t, normalOrder, o);
export const toBetaEtaNF = (t, o?) => run(t, normalOrderBetaEta, o);

const next = stepAt(cur, r.path, r.kind).reduct;   // was: stepAt(cur, r.path, "beta")
BULLET POINTS
  • βη-NF ⊆ β-NF ⊆ HNF ⊆ WHNF. Values are inside WHNF.
  • η is extensionality: a function that just forwards its argument to M is M.
  • WHNF fixes only the outer shape. λx. Ω is WHNF and still has no HNF.
  • Each normalizer is the strategy that stops exactly at its form.

07Brain Exercise

Think before you reveal

Fill the zoo yourself: find a term that is (1) β-normal but not βη-normal, (2) head normal but not β-normal, (3) weak head normal but not head normal.

(4), the real puzzle: find a term already in WHNF, so a lazy evaluator says "done" immediately, from which no amount of head reduction reaches head normal form. What does that say about using WHNF as "the answer"? The Lab checks all four slots.

Fill the zoo in the Lab
Reveal the answer

(1) λx. f x. (2) x ((λa. a) b). (3) λx. (λy. y) x. These are the zoo rows.

(4) λx. Ω, i.e. λx. (λy. y y) (λy. y y). It's a λ, so it's WHNF (and a CBV value) in zero steps. But under the λ sits Ω, and head reduction loops forever. It's unsolvable: no arguments you apply it to will ever make it produce a head variable.

So WHNF is a good stopping point for an evaluator (you know you have a function), and a poor definition of meaning. That's why theory prefers HNF: the unsolvable terms are exactly the ones with no HNF, and they can all be identified with each other consistently (Barendregt). Böhm trees (Module 34) build on that idea.

08There Are No Dumb Questions

Why would anyone want η?

Because λx. f x and f behave identically on every argument (P1.1). Without η, the calculus can't prove them equal. Compilers use η-reduction to remove wrapper functions, and η-expansion to make arities explicit.

Is η always safe in real languages?

Not quite. In a language with side effects or strictness, λx. f x delays evaluating f, but plain f doesn't. If computing f loops or prints, they differ. In the pure λ-calculus they never do.

Why do lazy languages stop at WHNF instead of going all the way?

Because often only the outer shape is needed ("is it a cons cell?"), and computing the rest might be expensive or infinite. Laziness means computing just enough.

Which form does print in a REPL use?

Usually full normal form, because you want to see everything. Module 12's REPL uses normal order to β-NF by default, with a command to switch strategies.
